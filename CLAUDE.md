## App overview

**TCG Life Counter** — cross-platform Flutter app (mobile + web) for tracking life points across multiple Trading Card Games. Currently shipped: Yu-Gi-Oh, MTG. Stubbed (no duel screen): Riftbound, Lorcana — gated in `_HomeScreenState` via `_selectedGame != SupportedTcg.riftbound && _selectedGame != SupportedTcg.lorcana`.

## State management

No Provider/Bloc/Riverpod. Pattern:

- `_HomeScreenState` is the root state holder — owns `AppSettings`, `List<GameRecord>`, `List<SideboardDeck>`, active `SupportedTcg`. Instantiates `AuthService` and `SyncService` and passes them down.
- Mutations: call `setState`, persist via `_persistState()` to SharedPreferences (JSON-encoded, versioned keys defined as static consts on `_HomeScreenState`), then `_syncService.markDirty()` so next auto-sync pushes.
- `AppRuntimeConfig` exposes `ValueNotifier<AppLanguage>` for live locale switching wrapped by `AppTextScope`.
- Services extend `ChangeNotifier`; screens subscribe via `AnimatedBuilder` or explicit listeners.

## Persistence

| Data | Where | Notes |
|------|-------|-------|
| Game records, sideboard decks, app settings, UX flags | `SharedPreferences` | JSON strings under versioned keys on `_HomeScreenState` |
| JWT token | `FlutterSecureStorage` | key `jwt_token`, read per request by `ApiClient` |
| Current user | `FlutterSecureStorage` | key `current_user`, JSON-encoded `AppUser` |

## Sync flow

`SyncService.syncNow()` runs a push then pull:

- **Push** — `onGetPayload` callback (wired in `_HomeScreenState`) serializes local state; POST `/api/v1/sync`.
- **Pull** — GET `/api/v1/sync?since=<ISO8601>`; `onApplyPull(Map)` callback merges into local state.
- **Always call `markDirty()` after a local mutation** or the next auto-sync won't push it.
- Conflict policy: last-write-wins by client `UpdatedAt` (server side).

## Auth flow

`AuthService.signInWithGoogle()` → Firebase Google provider (web popup) → Firebase ID token → POST `/api/v1/auth/firebase` → server JWT → `FlutterSecureStorage`. **Android/iOS native Google sign-in is TODO** (see `PLATFORM_TODO.md` and commit `c93730a`). Setup checklist for each platform lives in `PLATFORM_TODO.md`.

## i18n

Catalog is the `_catalog` map in [lib/l10n/app_strings.dart](lib/l10n/app_strings.dart) — EN + IT. Access strings anywhere with `AppTextScope.of(context).t('key')`. `flutter_localizations` is wired only for `MaterialApp.localizationsDelegates`. **Never hardcode user-facing strings** — add the key to `_catalog` with both locale entries.

## Models

All models are `@immutable` with manual `toJson()` / `fromJson()` / `copyWith()`. No codegen (`build_runner`, `freezed`, `json_serializable` are not used). Key entities:

- `AppSettings` — palette, per-player colors, gradient themes, language, default rules
- `GameRecord`, `MatchMetadata` — game history payload
- `SideboardDeck`, `SideboardMatchup` — sideboarding plans + matchup stats
- `AppUser` — server-authenticated user
- `SyncState` — last sync timestamp, dirty flag

## MTG specifics

MTG has its own setup + duel screens with resource counters (mana colors, poison, experience) and a `tableMode` layout. All MTG-specific logic stays in `lib/screens/mtg/`.

## Conventions

- Mobile is portrait-only — enforced by `AppOrientationLock.enforceMobilePortrait()` in `main()` plus a lifecycle observer.
- `wakelock_plus` keeps the screen on during active duels — **always release on duel exit** (back button, finish, dispose).
- Per-player colors and gradients live in `AppSettings` — read from there, do not hardcode hex values.
- Deck records link to match history for statistics — preserve referential integrity when editing deck or record IDs.
- History export/import: `.txt` file containing a versioned JSON payload.
- `SupportedTcg` enum + `supportedTcgStorageKeys` set live in [lib/core/constants.dart](lib/core/constants.dart) — adding a new TCG starts there.
